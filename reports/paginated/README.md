# Paginated inventory exception report

**Status: RDL 2016/01 XSD validation passed; connection, query/expressions,
pagination, and exports remain unverified in Power BI Report Builder.**

`InventoryExceptions.rdl` is a source definition for an A4 portrait report.
It queries the Inventory semantic model using the PBIDATASET provider, with
single-value Scenario and Policy parameters. The DAX dataset returns only
products with simulated unmet proxy units greater than zero, ordered by unmet
units descending and product ID ascending. It shows product, sales proxy,
unmet units, unit fill, and average closing inventory. The table header repeats
on subsequent pages, and the footer contains current/total page numbers.
The report includes the replay dates and hypothetical-inventory caveat.

The checked-in connection contains a deliberate `SEMANTIC_MODEL_ID` placeholder.
It cannot authenticate or execute until bound to a published, refreshed model.
No report data, tenant identifiers, or credentials are embedded.

## Runtime acceptance procedure

1. Complete the Power BI model's refresh and acceptance procedure first.
2. Publish the model to a suitable Power BI workspace. Open the RDL in Power BI
   Report Builder. Use **Add Power BI semantic model connection** to select that
   model and replace/rebind `InventoryModel`. Use the connection generated by
   Report Builder; the template string is not a deployment configuration.
3. Confirm the `Exceptions` dataset still uses that data source and binds its
   Scenario and Policy query parameters to the corresponding report parameters.
   Execute the dataset and check that the field mappings resolve `[Item]`,
   `[Demand]`, `[Unmet]`, `[Fill]`, and `[Stock]`. Fix provider-specific mappings
   in the source generator if the installed provider requires changes.
4. Run every scenario/policy combination. Compare product rows and totals against
   local `data/processed/simulation_products.parquet`, restricted to `lost_units > 0`.
   In the base case, unmet units must total 1,084 for fixed_cover and 1,285 for
   order_up_to. Fill values are product-specific; do not average them for cohort fill.
5. Check percent/numeric formatting, product order, repeated column headers,
   page numbers, no clipped text, and no blank horizontal pages. Check a no-row
   result with a separate synthetic all-fulfilled validation model.
6. Export to PDF and Excel. Compare row counts and numeric values, and inspect
   all pages. Record runtime version, evidence, and any corrections before
   marking native reporting complete.

The source can be inspected on macOS. Schema validation checks XML structure;
it does not execute DAX, authenticate a connection, or prove pagination.
The build script regenerates this RDL, so preserve changes or update its generator.
